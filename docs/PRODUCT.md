# Rokid Glasses 防灾产品落地范围

目标是佩戴眼镜即可获知所在地风险、及时看到可靠预警并采取行动。v0.2.0已实现所在地到一屏指南的前台流程，但还不具备替代手机/电视官方紧急播报的完整交付能力。

## 当前信息流

GPS / 语音或地址 / 地区列表 / 日本邮编 → 确认市町村（沿海另确认海啸预报区） → JMA预报与区域匹配电文 → 新鲜严重记录自动打开详情 → 按灾种的一屏离线指南 → GPS查询GSI指定紧急避难场所 → 网页地图或原生Hi Rokid导航交接。

明确的危险描述可直接进入离线指南，跳过联网和定位。未取得数据时显示未确认，不能给出“当前安全”。所在地选择和行动文本不依赖生成模型；模型不得生成震级、到达时间、避难地或路线安全性。

## 信息卡约束

| 灾种 | 可显示的来源字段 | 倒计时 |
| --- | --- | --- |
| 地震 | 对应市町村实测震度、震级M、震源、发生及发布时刻 | 当前无EEW，不显示揺れ到达秒数 |
| 海啸 | 确认沿岸、警报类别、预估高度、JMA明确的最早到达时刻 | 仅有该字段且数据新鲜时显示；不等倒计时，过时不显示负数 |
| 火山 | 对应火山/市町村、原文警戒类别、明确写出的数字等级 | 不预测喷发时刻 |
| 土砂、暴雨、洪水、高潮等 | 气象警报原文及其自身等级 | 不杜撰发生时刻 |

气象厅气象警报与地方政府“高龄者等避难/避难指示/紧急安全确保”是不同体系。当前没有地方政府指示接入，也没有完整全国有效警报的恢复/解除状态机。

## 达到替代产品之前的必要工作

1. **可靠灾害数据**：签约/接入可提供秒级EEW和可靠投递的服务，包含地区或坐标适用范围、预测震度/误差、到达时间依据、取消/订正及演练标记。不能把公开XML每分钟拉取改成高频请求就宣称获得EEW。
2. **常驻手机与眼镜通道**：核对Rokid Glasses、Rokid手机App/扩展能力和可用SDK；建立用户明确订阅与撤销、手机后台保持、眼镜休眠唤起、断线恢复、重复抑制、用户确认、延迟及投递失败监测。现有服务器通知模块是气象警报适配原型，没有真实发送验证。
3. **所在地持续性**：前台确认地址之后的移动与后台GPS更新，需要真机能力、权限、准确度、时间和隐私策略；静态邮编或市町村不能当作实时位置。海啸空间适用区需精确GIS匹配，替换目前的手动沿岸确认。
4. **真正的导航交接**：接入Rokid明确支持的导航调用协议或手机端适配，并核对所选目的地确为该灾种适用。海拔只能作地形信息；还需要海啸浸水区、建筑避难层、道路管制和地方政府临时信息，才能判断可行的避难路径。当前地图路线不作安全认证。
5. **佩戴验收**：日语ASR/TTS、显示可读性、镜腿操作、网络/电量/休眠、严重预警打断优先级、无网络已有指南、GPS被拒绝等都须在目标硬件验证；紧急时首要行动不能被操作/请求阻塞。

当前包不包含生产密钥、接收人或部署域名。上述外部能力未配置时，UI必须保留未接通状态，不能用模拟内容填补。
